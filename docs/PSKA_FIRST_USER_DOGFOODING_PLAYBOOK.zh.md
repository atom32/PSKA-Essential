# PSKA 第一用户自用手册

日期：2026-08-20

这份文档不是面向外部客户的功能说明，而是回答一个更具体的问题：

```text
徐大为作为 PSKA 的第一个真实用户，怎样把它用于自己的日常生活、工作、研究和创作？
```

核心目标不是“证明 PSKA 很酷”，而是让它每天真实地帮你：

- 少忘一点。
- 少重复想一点。
- 少让资料散掉一点。
- 让重要决定有出处。
- 让长期记忆可审查、可更新、可撤回。
- 让 Hermes 在回答你之前，先知道“这件事和你的过去有什么关系”。

## 1. 第一用户目标

PSKA 的第一用户不是普通消费者，而是你自己。你的需求有几个特点：

- 长期项目多：PSKA、Hermes、Eidolia、GBrain、知识图谱、RAG、量化研究、创作项目。
- 资料来源杂：本地文件、ChatGPT 对话、代码仓库、手册、论文、财报、个人笔记、画布 thought。
- 记忆层次复杂：身份、项目目标、工作习惯、创作偏好、私密人生档案、公司上下文都混在一起。
- 你不是只想“搜文件”，而是想保留个人认知连续性。

所以第一阶段 dogfooding 不要追求“替我管理一切”。先追求四个日常闭环：

```text
记录今天发生了什么
  -> 找回过去相关的资料和记忆
  -> 辅助当前判断
  -> 把真正值得长期保留的内容沉淀为记忆卡
```

## 2. 不要把 PSKA 当成什么

PSKA 现在不应该被当成：

- 新的日历软件。
- 新的待办软件。
- 新的网盘。
- 新的笔记软件。
- 新的聊天前端。
- 自动替你删除文件的清理工具。
- 自动把所有聊天都变成记忆的人格模拟器。

它现在更适合当作：

```text
个人认知控制层
```

也就是：别的工具继续做自己擅长的事，PSKA 负责把来源、证据、记忆、审核、追踪和智能体调用接起来。

## 3. 第一阶段只吃五类资料

为了避免一上来就把生活搞成数据工程，建议第一阶段只纳入五类资料。

### 3.1 每日流水

目的：给未来的自己留下时间线。

每天只写几行，不要写成长篇日记：

```text
今天做了什么？
今天答应了谁什么事？
今天有什么重要情绪或身体状态？
今天有什么值得以后记住的判断？
今天有哪些资料需要回头整理？
```

建议文件夹：

```text
/Users/xudawei/PSKA-Dogfood/daily
```

示例文件：

```text
2026-08-20.md
```

示例内容：

```markdown
# 2026-08-20

## 今天发生

- 继续整理 PSKA 的第一用户 dogfooding 方式。
- 发现之前的用户手册偏功能清单，不够贴近日常使用。

## 承诺和待办

- 把 PSKA 的日常自用流程做成固定模板。
- 后续导入完整 ChatGPT 对话记录。

## 身体和情绪

- 今天如果记忆力、脾气、疲劳感有明显变化，简单记一行，不做医学结论。

## 值得沉淀

- PSKA 的第一用户目标应从“展示功能”转成“每天帮我恢复上下文”。
```

### 3.2 决策记录

目的：以后能回答“我当时为什么这样选”。

适合记录：

- 项目方向选择。
- 架构取舍。
- 是否引入某个开源组件。
- 公司产品定位。
- 家庭资产或大额支出决策。
- 创作世界观或角色路线选择。

模板：

```markdown
# 决策：是否把 GBrain 作为 PSKA 组件吸纳

## 时间

2026-08-20

## 背景

PSKA 自己做完整记忆系统会很重；GBrain 可能已有更成熟的记忆组织能力。

## 备选项

- PSKA 自建所有记忆能力。
- GBrain 作为 PSKA-Components 中的可替换组件。
- 完全放弃 PSKA 记忆层，只依赖智能体。

## 当前判断

GBrain 可以吸纳，但不能绕过 PSKA 的 SourceRef、Review、Audit 和 Memory Card。

## 以后如何验证

- 看 GBrain fact 能否反查来源。
- 看 Hermes 回答时是否能引用这些记忆。
- 看记忆是否可以更新、撤回、替代。
```

### 3.3 项目状态

目的：让 Hermes 不再每次都从零理解项目。

适合项目：

- PSKA。
- Hermes。
- Eidolia。
- GBrain 适配。
- DeepSeek Harness 研究。
- 量化研究。
- 公司产品材料。
- 小说和世界观创作。

每个项目保持一个 `project-state.md`：

```markdown
# PSKA 项目状态

## 当前目标

把 PSKA 从胶水层推进为个人外部认知系统。

## 当前边界

- 没有独立前端。
- 主入口是 Hermes WebUI extension。
- PSKA 负责后端控制、来源、审核、记忆和追踪。

## 最近进展

- 已完成 ChatGPT 记忆摘要导入。
- 已验证 GBrain fact 2-11 可作为 active memory。
- 已写出第一用户自用手册。

## 近期问题

- 完整 ChatGPT 对话还未导入。
- Hermes WebUI extension 中的用户路径还需要继续补齐。
```

### 3.4 私密人生档案

目的：保存人生连续性，但不随便暴露。

这类资料可以进入 Source Archive，但默认不拆成普通长期记忆。PSKA 里已经有一条保护边界记忆：

```text
fact 5: 私密人生回忆应作为个人档案和创作母题来源保存，默认不应被压缩成普通长期行为记忆，也不应在无关任务中主动暴露具体人物和亲密细节。
```

使用原则：

- 可以归档。
- 可以在你明确要求时用于自传、创作母题、人生复盘。
- 不在普通技术问答、公司材料、日常建议里主动出现。
- 不把具体人物和亲密细节变成到处触发的长期记忆。

更好的沉淀方式是：

```text
原始回忆 -> 私密 source archive
  -> 抽象母题或保护边界
  -> Review
  -> 必要时才写入长期记忆
```

### 3.5 身体、情绪和认知状态

目的：长期观察，不做自动诊断。

考虑到你提到新冠、带状疱疹之后的脾气和记忆变化，以及家族老人认知衰退的担忧，这一类值得记录，但必须谨慎。

每天最多记几个低负担指标：

```text
睡眠：好 / 一般 / 差
精力：好 / 一般 / 差
记忆：正常 / 有点卡 / 明显异常
脾气：平稳 / 易烦 / 明显失控
身体：疼痛、头晕、发热、皮疹、其他
备注：一句话
```

PSKA 可以做：

- 帮你找回一段时间内的记录。
- 总结“最近两周是否更易怒或更疲劳”。
- 提醒你把明确、持续、加重的问题拿去咨询医生。
- 帮你准备就医时要说的时间线。

PSKA 不应该做：

- 给出医学诊断。
- 替代医生。
- 因为一天状态不好就做长期人格判断。
- 把“今天脾气差”写成“用户就是脾气差的人”。

### 3.6 ChatGPT 记忆摘要

目的：把现有 ChatGPT 个性化记忆先变成可审核候选，而不是一次性灌入长期记忆。

用法：

```bash
curl -fsS http://127.0.0.1:8765/api/memory/chatgpt-summary/import \
  -H 'Content-Type: application/json' \
  -d @chatgpt-memory-import.json
```

其中 `chatgpt-memory-import.json` 可以只包含：

```json
{
  "source_label": "ChatGPT 个性化记忆摘要",
  "candidate_limit": 12,
  "text": "这里粘贴 ChatGPT 个性化-记忆-记忆摘要"
}
```

这条路径只会创建 pending Review candidates：

- 不直接写 GBrain。
- 不修改任何本地资料文件。
- 不需要 embedding。
- 默认跳过私密人生、家庭、健康和亲密经历段落。
- 如果发现私密段落，只创建一条“默认不要在无关任务里暴露”的边界候选。

### 3.7 ChatGPT 完整对话档案

目的：把 `conversations.json` 或 ChatGPT 导出 zip 变成可检索的资料档案，而不是直接变成长期记忆。

用法：

```bash
curl -fsS http://127.0.0.1:8765/api/sources/chatgpt-conversations/import \
  -H 'Content-Type: application/json' \
  -d '{
    "export_path": "/path/to/conversations.json",
    "source_label": "ChatGPT 完整对话档案",
    "conversation_limit": 100,
    "scan": true
  }'
```

这条路径只会写入 PSKA 管理的 markdown 档案并注册为本地资料源：

- 不修改 ChatGPT 原始导出文件。
- 不直接写 GBrain。
- 不创建记忆审核项。
- 不需要 embedding。
- 后续先用 source search/read 找证据，再挑选稳定事实进入记忆审核。

导入后先打开 Hermes WebUI 的 PSKA Memory 页面，看 Review Queue。只把稳定身份、长期项目、
工作习惯、明确偏好和保护边界 apply 到长期记忆；长篇人生回忆先留在 private source archive。

## 4. 每天怎么用

### 4.1 早上：问今天的上下文

在 Hermes WebUI 里问：

```text
基于 PSKA 当前记忆、项目状态和最近资料，今天我最该先恢复哪些上下文？
请分成：必须处理、可以推进、暂时不要碰。
```

理想情况下，PSKA 应该给 Hermes 准备：

- 最近 active 记忆。
- 待处理 Review。
- 最近项目状态。
- 本地每日流水。
- 最近 source audit 或 digest 结果。

现阶段如果自动数据还不全，可以先从你手动维护的 daily/project 文件夹开始。

### 4.2 工作前：让它先恢复项目状态

比如开始做 PSKA：

```text
我要继续做 PSKA。先不要写代码。
请从 PSKA 项目状态、最近手册、记忆卡和 trace 里恢复当前上下文：
1. 我们现在做到哪里了？
2. 目前哪些路线不能再走？
3. 下一步最小可验证动作是什么？
```

这比直接问“接下来做什么”更好，因为它强迫系统先恢复上下文，而不是凭印象答。

### 4.3 研究资料时：先召回，再判断

比如你要研究某个组件：

```text
请先从我的本地资料和已记录的 PSKA 方案里召回与 GBrain 组件化有关的内容。
先列来源，再给判断，不要直接下结论。
```

如果资料在本地文件夹，用 Source Recall。

如果资料已经进入 RAGFlow，用 dataset scope。

如果是你以前形成过的判断，用 memory search。

### 4.4 做决定时：让它写决策草稿

不要只让 AI 给建议，而是让它帮你形成可追溯决策：

```text
请把这次关于“是否让 GBrain 成为 PSKA 组件”的讨论整理成一条决策记录。
要求包括：背景、备选项、当前判断、证据、风险、以后如何验证。
先作为草稿，不要直接写长期记忆。
```

然后你确认后，把草稿放进 `decisions` 文件夹。只有其中真正会影响未来行为的内容，再进入 Memory Review。

### 4.5 晚上：做一天的收束

晚上不要让它长篇大论。问：

```text
请根据今天我记录的 daily、项目文件和对话，总结：
1. 今天完成了什么？
2. 有哪些承诺还没闭环？
3. 哪些内容值得变成长期记忆候选？
4. 哪些内容只应该留在 source archive，不要写记忆？
```

这个问题很重要，因为它把“记录生活”和“污染长期记忆”分开了。

## 5. 每周怎么用

每周一次，做一次轻量复盘：

```text
请基于过去 7 天的 daily、项目状态、决策记录和记忆卡，帮我做一份周复盘。
分成：
1. 我实际推进了什么。
2. 我反复卡在哪些地方。
3. 哪些判断发生了变化。
4. 哪些记忆应该新增、更新、合并或废弃。
5. 下周只选 3 个最重要动作。
```

周复盘不要直接写记忆。它应该先生成候选：

```text
候选记忆 -> Review Queue -> 人确认 -> GBrain
```

## 6. 典型生活场景

### 6.1 “我忘了这个项目为什么这么设计”

问：

```text
PSKA 最初为什么坚持 SourceRef、Review、Audit 和 Memory Card？
请按时间线回答，并区分：当时的来源、我的判断、后来被验证的部分、后来被修正的部分。
```

PSKA 应该调：

- 项目状态文件。
- 技术方案文档。
- 记忆卡 fact 4、9。
- Review 和 trace。
- 相关 source refs。

### 6.2 “我今天状态不太对”

记录：

```text
记一条日常状态：今天睡眠差，下午明显易烦，工作时有几次想不起刚才要做什么。只作为 health log，不写长期人格记忆。
```

以后问：

```text
请帮我回顾最近两周的睡眠、情绪和记忆状态，只列趋势和原始记录，不做医学诊断。
```

### 6.3 “我想写小说，但忘了以前的母题”

问：

```text
请从我的创作记忆和 Eidolia 相关资料里召回政治元叙事、苏联电影风格、战争废墟、红头巾女孩、巅峰谢幕这些母题。
先列我以前保留过的设定，再给今天可继续写的 3 个切入点。
```

PSKA 应该使用：

- 创作项目 source archive。
- fact 10。
- Eidolia thought/artifact。
- 相关对话导入后的候选。

### 6.4 “我要写公司材料”

问：

```text
请基于我的身份记忆、公司记忆和产品线记忆，帮我起草一版天大智图的公司介绍。
要求不要引用私密人生回忆，只使用职业和公司相关上下文。
```

会用到：

- fact 6：职业身份。
- fact 7：公司上下文。
- fact 8：产品线。
- fact 11：dogfooding 业务领域。
- 不触发 fact 5 保护的私密内容。

### 6.5 “我和家里讨论了一个长期安排”

记录到 source，不直接记忆：

```text
今天和家里讨论了某个长期安排。请帮我整理成 private source note：
背景、参与人、当前共识、未决问题、下次需要确认什么。
不要写长期记忆，除非我之后明确要求。
```

原因：家庭资产、亲密关系、子女安排都属于高隐私内容。适合归档，不适合默认成为智能体到处使用的长期记忆。

```text
/Users/xudawei/PSKA-Dogfood
```

内部结构：


建议权限：

| 文件夹 | 初始权限 | 原因 |
| --- | --- | --- |
| daily | sidecar_write | 可以打标签和评论，但不改原文 |
| decisions | sidecar_write | 适合加来源和状态 |
| projects | sidecar_write | 项目状态需要持续维护 |
| health | read_only | 先只读，避免误写 |
| private-archive | read_only | 私密资料只归档，不随便改 |
| reading | sidecar_write | 适合标签、摘要、评论 |
| creative | sidecar_write | 可与 Eidolia 互相引用 |
| company | read_only 或 sidecar_write | 视资料敏感度决定 |

第一周不要接太多。建议先接：

```text
daily/
decisions/
projects/pska/
creative/
```

## 8. 哪些内容应该进入长期记忆

可以进入长期记忆的内容，必须满足至少一个条件：

- 以后经常影响回答。
- 代表稳定偏好。
- 是长期项目状态。
- 是需要保护的排除规则。
- 是身份、公司、产品等稳定背景。
- 是已经确认过的工作习惯。

好记忆示例：

```text
用户讨论 PSKA 时，优先关注个人认知连续性，而不是只关注 RAG 或 Agent 工程实现。
```

坏记忆示例：

```text
用户今天有点烦。
```

更好的处理：

```text
今天有点烦 -> health/daily source note
最近两个月持续易烦并影响工作 -> 趋势报告，提醒用户考虑医学或生活干预
```

## 9. 第一周 dogfooding 计划

### 第 1 天：建生活资料根目录

动作：

- 建 `PSKA-Dogfood` 目录。
- 建 `daily`、`decisions`、`projects/pska`。
- 写今天的 daily。
- 写一条 PSKA 项目状态。

验证：

- PSKA 能扫描这些文件。
- Source Recall 能搜到“今天完成了什么”。

### 第 2 天：用它恢复一个项目上下文

动作：

- 开始工作前问 Hermes：“先帮我恢复 PSKA 当前上下文。”
- 要求它必须列来源。
- 把回答中不准的地方纠正。

验证：

- 它能用项目状态和现有记忆。
- 它不会把诊断页误当成产品前端。

### 第 3 天：写一条决策记录

动作：

- 选一个真实决策，例如 GBrain 是否纳入 PSKA Components。
- 让 Hermes 整理决策草稿。
- 你修改后保存到 `decisions`。

验证：

- 一周后能问回“当时为什么这么决定”。

### 第 4 天：做一次记忆候选审核

动作：

- 从前三天的 daily 和 decisions 里提取候选记忆。
- 只选 1 到 3 条。
- 进入 Review Queue。
- 只 apply 真正有长期价值的。
- 如果候选来自一次 Hermes 回答，先在 Recent Answer Proofs 点开 `View Trace`，
  再用 `Draft Memory Candidate` 起草；必须改写成稳定记忆后再创建审核候选。

验证：

- Memory health 仍然是 0 issue。
- 新记忆有 type、scope、behavior_delta 和 source_refs。
- 来自回答的候选可以 trace 回对应 answer proof。

### 第 5 天：接入创作

动作：

- 选一个 Eidolia thought 或创作文件。
- 让 PSKA 召回相关创作母题。
- 生成一个“下一段怎么写”的建议。

验证：

- 它能使用 fact 10。
- 它不会把私密人生细节直接暴露到无关创作里，除非你明确要求。

### 第 6 天：做一次身体和情绪记录回顾

动作：

- 看过去几天 health/daily。
- 让 PSKA 只总结趋势，不诊断。

验证：

- 它会说“这不是医学诊断”。
- 它能保留原始记录和时间线。

### 第 7 天：周复盘

动作：

- 让 PSKA 总结一周。
- 列出 3 个下周动作。
- 列出可新增、更新、合并、废弃的记忆候选。

验证：

- 候选不会直接写入长期记忆。
- 需要你确认后才 apply。

## 10. 产品改进从哪里来

作为第一用户，你每天遇到的摩擦就是产品需求。建议记录成三类：

### 10.1 捕捉太麻烦

例如：

```text
我不想打开文件写 daily。
```

产品需求：

- Hermes 里一句话创建 daily note。
- 自动带日期。
- 自动写到 source archive。
- 不直接写长期记忆。

### 10.2 找回不准

例如：

```text
我明明记过 GBrain 的事，但召回不到。
```

产品需求：

- 更好的 Source Recall。
- 更好的项目状态索引。
- Memory Card 和 SourceRef 的联合召回。
- 召回失败时能解释搜了哪里。

### 10.3 记忆太泛

例如：

```text
它又想把“我重视知识管理”这种废话写成记忆。
```

产品需求：

- 更严格的记忆质量门。
- 必须有行为影响。
- 必须有作用范围。
- 必须有来源。
- 私密内容默认只归档。

## 11. 判断 dogfooding 是否成功

第一阶段成功不看“功能有多少”，看这些问题：

```text
我今天有没有少忘一件事？
我有没有找回一个过去判断？
我有没有少重复解释一次项目背景？
我有没有把一个重要决定留下来源？
我有没有避免把垃圾摘要写进长期记忆？
我有没有在需要时保护住私密内容？
```

如果答案经常是“有”，PSKA 就开始对你的日常生活产生价值了。

## 12. 最小可行日常版本

如果只保留最小流程，每天就做三件事：

```text
早上：问“今天我该恢复什么上下文？”
白天：遇到重要决定就让它写 decision note。
晚上：问“今天哪些只归档，哪些值得成为记忆候选？”
```

每周只做一件事：

```text
周复盘，清理记忆候选，只 apply 真的会影响未来回答的内容。
```

这就是第一用户阶段最现实的 PSKA：不是全知全能，而是每天帮你把一点点个人认知从易散失的对话和文件里，移到可追溯、可审查、可恢复的外部系统里。
